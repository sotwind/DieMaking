# 日期范围查询修复计划

## 问题描述

用户选择日期范围"2026/2/26 至 2026/3/8"进行查询，但结果却包含了3月9日的数据（2026/3/9 8:43）。

## 根本原因分析

问题在于 `DieService.cs` 和 `DieServiceOptimized.cs` 中的结束日期处理方式：

```csharp
// 当前有问题的代码 (DieService.cs:76-80)
if (endDate.HasValue)
{
    conditions.Add("d.CreateTime <= @EndDate");
    parameters.Add(new SqlParameter("@EndDate", endDate.Value.AddDays(1)));
}
```

**问题分析：**
1. 用户选择3月8日作为结束日期
2. 代码使用 `AddDays(1)` 将其转换为 3月9日 00:00:00
3. SQL查询条件是 `CreateTime <= 3月9日 00:00:00`
4. 但数据库中的数据包含时间部分（如 2026/3/9 8:43）
5. 由于 8:43 > 00:00:00，所以 3月9日的数据被错误地包含进来了

**正确的处理方式应该是：**
- 使用 `AddDays(1).AddSeconds(-1)` 将结束日期设置为当天的 23:59:59
- 或者使用 `AddDays(1)` 但将SQL条件改为 `<` 而不是 `<=`

## 修复方案

### 方案选择

有两种修复方式：

**方案A：在服务层修复（推荐）**
- 修改 `DieService.cs`、`DieServiceOptimized.cs`、`DieService_Paged.cs`
- 将 `AddDays(1)` 改为 `AddDays(1).AddSeconds(-1)`
- 优点：统一修复，所有调用方自动受益

**方案B：在UI层修复**
- 修改各个窗体文件，在传递参数前处理日期
- 缺点：需要修改多处，容易遗漏

**采用方案A**，在服务层统一修复。

## 修复后的代码示例

```csharp
// 修复后的代码
if (endDate.HasValue)
{
    conditions.Add("d.CreateTime <= @EndDate");
    // 将结束日期设置为当天的 23:59:59，确保包含整天数据
    parameters.Add(new SqlParameter("@EndDate", endDate.Value.Date.AddDays(1).AddSeconds(-1)));
}
```

## 注意事项

1. 使用 `.Date` 属性确保先清除时间部分，再添加天数和秒数
2. `AddDays(1).AddSeconds(-1)` 会将日期转换为当天的最后一秒（23:59:59）
3. 这样查询条件 `<= 23:59:59` 就能正确包含当天的所有数据
