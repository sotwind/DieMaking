# 刀模管理 - "保存草稿"功能分析

## 当前实现的问题

经过代码分析，发现**当前的"保存草稿"功能实际上没有实现任何特殊逻辑**，它与"保存"按钮执行完全相同的操作。

### 代码位置
- 文件：`Forms/Die/DieAddForm.cs`
- 相关行：413-421, 481-542

### 当前逻辑

```csharp
// 保存按钮点击
private void BtnSave_Click(object? sender, EventArgs e)
{
    SaveDie(false);  // isDraft = false
}

// 保存草稿按钮点击
private void BtnSaveDraft_Click(object? sender, EventArgs e)
{
    SaveDie(true);   // isDraft = true
}

// 保存方法
private void SaveDie(bool isDraft)
{
    // ... 验证代码 ...
    
    var die = new DieInfo
    {
        // ... 其他属性 ...
        AuditStatus = isDraft ? AuditStatus.Unaudited : AuditStatus.Unaudited,  // 问题所在！
        // ...
    };
    
    // 保存到数据库（新增或更新）
}
```

### 问题点

**第542行的三元表达式有问题：**
```csharp
AuditStatus = isDraft ? AuditStatus.Unaudited : AuditStatus.Unaudited
```

无论 `isDraft` 是 `true` 还是 `false`，结果都是 `AuditStatus.Unaudited`（未审核）。

这意味着：
- ✅ **保存** → AuditStatus = 未审核
- ✅ **保存草稿** → AuditStatus = 未审核

两个按钮执行的结果完全一致！

## "保存草稿"功能的常见业务逻辑

在业务系统中，"保存草稿"通常有以下用途：

### 1. 草稿状态标记
- 草稿数据可以被标记为"草稿"状态
- 草稿数据不参与正式业务流程（如审核、生产排程等）
- 草稿数据可以被继续编辑，直到用户确认"正式保存"

### 2. 部分保存
- 允许用户保存不完整的表单数据
- 跳过某些必填字段的验证
- 方便用户分多次填写复杂表单

### 3. 临时存储
- 数据暂存，不立即进入正式流程
- 可以稍后继续编辑
- 正式保存后才触发后续业务流程

## 建议的改进方案

### 方案A：添加草稿状态字段（推荐）

1. **数据库修改**：在 `DM_DieInfo` 表添加 `IsDraft` 字段
2. **模型修改**：`DieInfo` 类添加 `IsDraft` 属性
3. **业务逻辑**：
   - 保存草稿：`IsDraft = true`，跳过部分验证
   - 正式保存：`IsDraft = false`，执行完整验证
4. **列表筛选**：刀模列表默认不显示草稿数据，或单独显示

### 方案B：使用审核状态区分

修改现有逻辑：
```csharp
// 保存草稿 - 保持未审核状态，但可能有其他标记
AuditStatus = AuditStatus.Unaudited;
// 可以添加其他逻辑，如记录草稿时间等

// 正式保存 - 直接提交审核或标记为待审核
AuditStatus = AuditStatus.Unaudited; // 或 Audited，根据业务需求
```

### 方案C：移除保存草稿按钮

如果业务上不需要草稿功能，可以直接移除该按钮，简化界面。
