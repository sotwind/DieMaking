# 审核状态对生产看板影响分析

## 问题概述

用户询问"待生产状态"和"审核状态"对生产看板的影响。经过代码分析，发现了一个重要问题：

## 关键发现

### 1. 两个状态的定义

| 状态类型 | 枚举值 | 说明 |
|---------|--------|------|
| **刀模状态 (DieStatus)** | Pending = 0 | 待生产 |
| | InProgress = 1 | 生产中 |
| | Completed = 2 | 已完成 |
| | OnHold = 3 | 暂不生产 |
| | NotRequired = 4 | 无需生产 |
| **审核状态 (AuditStatus)** | Unaudited = 0 | 未审核 |
| | Audited = 1 | 已审核 |

### 2. 当前生产看板的查询逻辑（存在问题）

**文件**: `Services/ProductionService.cs`

```csharp
// 获取生产看板数据 - 按状态分组
public ProductionBoardData GetProductionBoardData(...)
{
    var data = new ProductionBoardData();
    
    // 获取待生产刀模 - 只根据 Status 筛选，未考虑 AuditStatus
    data.PendingList = GetDieListByStatus(DieStatus.Pending, ...);
    
    // 获取生产中刀模 - 只根据 Status 筛选，未考虑 AuditStatus
    data.InProgressList = GetDieListByStatus(DieStatus.InProgress, ...);
    
    // 获取已完成刀模 - 只根据 Status 筛选，未考虑 AuditStatus
    data.CompletedList = GetDieListByStatus(DieStatus.Completed, ...);
    
    return data;
}
```

**SQL查询条件**:
```sql
WHERE d.Status = @Status  -- 没有 AuditStatus 条件
```

### 3. 问题分析

**当前行为**:
- 生产看板显示所有"待生产"状态的刀模，**无论是否已审核**
- 未审核的刀模也会出现在生产看板中

**可能的问题**:
- 如果业务逻辑要求"只有审核通过的刀模才能进入生产环节"，那么当前实现存在逻辑漏洞
- 未审核的刀模可能不应该出现在生产看板中

### 4. 审核功能逻辑

**审核按钮位置**: 刀模列表界面 (`DieListForm.cs`)

**审核操作**:
- 点击"审核"按钮可切换刀模的审核状态（未审核 ↔ 已审核）
- 审核后只更新 `AuditStatus` 字段，不影响 `Status` 字段

## 建议方案

### 方案一：生产看板只显示已审核的刀模（推荐）

修改 `ProductionService.cs` 中的查询逻辑，增加 `AuditStatus = 1`（已审核）的筛选条件：

```csharp
// 修改后的查询条件
WHERE d.Status = @Status AND d.AuditStatus = 1  -- 只显示已审核的
```

**适用场景**: 如果业务要求"只有审核通过才能开始生产"

### 方案二：保持现状

**适用场景**: 如果业务允许"先排产再审核"或"审核与生产看板无关"

### 方案三：生产看板增加审核状态筛选

在生产看板界面增加审核状态筛选条件，让用户自行决定显示哪些数据。

## 需要确认的问题

1. 业务上是否要求"只有审核通过的刀模才能进入生产环节"？
2. 未审核的刀模是否应该显示在生产看板中？
3. 是否需要-Leo-在生产看板中区分显示已审核和未审核的刀模？
