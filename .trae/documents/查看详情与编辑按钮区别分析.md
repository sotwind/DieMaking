# 查看详情按钮与编辑按钮的区别分析

## 概述

在刀模管理系统中，**查看详情**按钮和**编辑**按钮虽然都打开同一个表单（DieAddForm），但它们在功能定位、使用场景和用户体验上有明显区别。

---

## 核心区别对比

| 维度 | 编辑按钮 | 查看详情按钮 |
|------|---------|-------------|
| **主要用途** | 修改数据 | 浏览数据 |
| **权限控制** | 已审核数据不能编辑 | 任何状态的数据都可以查看 |
| **表单模式** | 编辑模式（可修改） | 查看模式（只读） |
| **保存按钮** | 显示"保存"按钮 | 不显示"保存"按钮 |
| **取消按钮** | 显示"取消"按钮 | 显示"关闭"按钮 |
| **控件状态** | 所有输入框可编辑 | 所有输入框只读/禁用 |

---

## 权限上的区别

### 当前权限控制情况

**目前代码中，两个按钮都没有做用户权限的细粒度控制**，只有**数据状态（审核状态）**的控制：

```csharp
// 编辑按钮的权限检查 - 只检查了审核状态，没有检查用户权限
private void BtnEdit_Click(object? sender, EventArgs e)
{
    var die = GetSelectedDie();
    if (die == null) return;

    // 只检查了数据是否已审核，没有检查用户是否有"修改刀模"权限
    if (die.AuditStatus == AuditStatus.Audited)
    {
        MessageBox.Show("已审核的刀模不能编辑", "提示", MessageBoxButtons.OK, MessageBoxIcon.Warning);
        return;
    }
    // ...
}

// 查看详情按钮 - 没有任何权限检查
private void BtnView_Click(object? sender, EventArgs e)
{
    var die = GetSelectedDie();
    if (die == null) return;

    // 没有任何权限检查，任何人都可以查看
    var form = new DieAddForm(die.DieID, true);
    form.ShowDialog(this);
}
```

## 代码实现差异

### 1. 列表页面按钮点击事件

#### 编辑按钮 (BtnEdit_Click)

### 3. 表单界面差异

#### 编辑模式
- 窗口标题：`"编辑刀模"`
- 显示"保存"按钮
- 显示"取消"按钮
- 所有输入框可编辑

#### 查看模式
- 窗口标题：`"查看刀模"`
- **不显示**"保存"按钮
- 显示"关闭"按钮（而非"取消"）
- 所有输入框**只读/禁用**

```csharp
// 根据模式设置窗口标题
this.Text = _isViewMode ? "查看刀模" : (_dieId.HasValue ? "编辑刀模" : "新增刀模");

// 查看模式下不显示保存按钮
if (!_isViewMode)
{
    btnSave = UIStyleHelper.CreateSaveButton();
    btnSave.Location = new Point(250, btnY);
    btnSave.Click += BtnSave_Click;
    this.Controls.Add(btnSave);
}

// 查看模式下按钮文字为"关闭"
btnCancel = UIStyleHelper.CreateCancelButton(_isViewMode ? "关闭" : "取消");

// 查看模式下禁用所有编辑控件
if (_isViewMode)
{
    SetControlsReadOnly(this, true);
}
```

### 4. 控件只读设置

```csharp
private void SetControlsReadOnly(Control parent, bool readOnly)
{
    foreach (Control ctrl in parent.Controls)
    {
        if (ctrl is TextBox txt)
            txt.ReadOnly = readOnly;        // 文本框设为只读
        else if (ctrl is ComboBox cmb)
            cmb.Enabled = !readOnly;        // 下拉框禁用
        else if (ctrl is DateTimePicker dtp)
            dtp.Enabled = !readOnly;        // 日期选择器禁用
        else if (ctrl is DataGridView dgv)
            dgv.ReadOnly = readOnly;        // 数据表格只读
        else if (ctrl is Button btn && btn != btnCancel)
            btn.Enabled = !readOnly;        // 按钮禁用（除了关闭按钮）

        if (ctrl.HasChildren)
            SetControlsReadOnly(ctrl, readOnly);
    }
}
```

## 使用场景

### 编辑按钮的使用场景
1. 需要修改刀模信息时
2. 数据状态为"未审核"时才能使用
3. 修改后需要保存数据

### 查看详情按钮的使用场景
1. 只想浏览数据，不想修改
2. 查看已审核的数据（不能编辑）
3. 查看数据详情确认信息
4. 双击数据行时默认触发查看详情

---

## 为什么需要两个按钮？

### 1. 权限控制
- 已审核的数据不应该被修改，但需要能被查看
- 通过"编辑"按钮限制已审核数据的修改权限
- 通过"查看详情"按钮保证任何数据都可被查看

### 2. 用户体验
- **编辑模式**：用户明确知道自己可以修改数据
- **查看模式**：用户明确知道这是只读浏览，不会误操作修改数据
- 防止用户无意中修改了重要数据

### 3. 业务逻辑
- 审核后的数据是"锁定"状态，不能编辑
- 但业务上需要能够查看已审核数据的详细信息
- 两个按钮分别满足不同的业务需求

---

## 总结

| 场景 | 应该使用 |
|------|---------|
| 要修改未审核的数据 | 编辑按钮 |
| 要查看已审核的数据 | 查看详情按钮 |
| 只想浏览不修改 | 查看详情按钮 |
| 双击数据行 | 查看详情（默认行为） |

### 关于权限的总结

**目前代码中两个按钮都没有做用户权限的细粒度控制**，只有数据状态的检查：

- **编辑按钮**：只检查了数据是否已审核，没有检查用户是否有"修改刀模"权限
- **查看详情按钮**：没有任何权限检查

如果需要完善权限控制，应该：
1. 给编辑按钮增加 `CurrentUser.HasPermission(PermissionKeys.DieEdit)` 检查
2. 可选给查看详情按钮增加 `CurrentUser.HasPermission(PermissionKeys.DieManage)` 检查

两个按钮虽然打开同一个表单，但**功能定位完全不同**：
- **编辑按钮** = 修改数据（有数据状态限制）
- **查看详情按钮** = 浏览数据（无数据状态限制，只读）
